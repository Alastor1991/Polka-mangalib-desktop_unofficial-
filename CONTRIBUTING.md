# Как участвовать

Спасибо, что хотите помочь Полке. Перед началом прочитайте [docs/architecture.md](docs/architecture.md): там описано, как устроен код и какие гарантии держит каждая часть.

## Сборка и проверки

```sh
cargo build
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

CI на каждый пуш делает то же самое, и PR с красной сборкой не принимается.

Живые проверки против настоящего API лежат отдельно и помечены `#[ignore]`:

```sh
cargo test -p libsocial --test live -- --ignored --test-threads=1
```

Запускайте их, когда меняете что-то в работе с API. Гонять их в цикле не надо, это нагрузка на чужой сервис.

## Правила, которые не обсуждаются

1. Платный контент не обходится. Закрытые главы и ранний доступ открываются только тем, кто купил их на своём аккаунте. PR, который это меняет, будет закрыт.
2. Сервис не перегружается. Не убирайте ограничение частоты, повторы с паузой и паузы загрузчика, не поднимайте параллельность сверх 8. Скорость ищите в кэше: число запросов к сервису увеличивать нельзя.
3. Чужие плееры не вскрываются. Kodik открывается в браузере, его потоки мы не достаём.
4. Клиент не выдаёт себя за другие приложения: свой `User-Agent`, никаких чужих `client_id`, кроме публичного веб-клиента сайта и клиента, который выдадут Полке сами разработчики сервиса.
5. В репозиторий не попадает чужой контент и личные данные: страницы глав, токены, ники пользователей в фикстурах.

## Как устроить изменение

- Новый запрос к API: метод в `crates/libsocial` и модель в `models.rs`. Снимите настоящий ответ (`polka dev-get <сайт> <путь>`), уберите из него поля просмотра и ники, положите в `crates/libsocial/tests/fixtures` и напишите тест разбора в `tests/fixtures.rs`.
- Логика клиента (повторы, зеркала, токен) проверяется на мок-сервере в `tests/client.rs`, без сети.
- Загрузчик проверяется так же: задания целиком на мок-сервере в `job_tests` в `crates/polka-core/src/downloads.rs`. Если меняете поведение очереди, паузы, удаления или докачки, добавьте туда сценарий.
- Схема базы меняется только новой миграцией в конце `MIGRATIONS` в `crates/polka-core/src/db.rs`. Старые миграции не трогайте: они уже применены у пользователей.
- Интерфейс проверяйте глазами. Запустите окно на нужном экране (`POLKA_DEV_OPEN`, `POLKA_DEV_TAB`) с отдельными каталогами данных, чтобы не трогать свою библиотеку:

  ```sh
  XDG_DATA_HOME=/tmp/polka-dev/data XDG_CACHE_HOME=/tmp/polka-dev/cache \
  POLKA_DEV_OPEN=mangalib:7965--chainsaw-man:0 cargo run
  ```

## Код

- Комментарии и сообщения пользователю пишутся на русском.
- Комментарий объясняет, зачем код устроен именно так. Пересказывать код словами не нужно.
- Ошибки, которые видит пользователь, говорят, что случилось и что делать, без служебных подробностей.
- Токены и пароли не попадают в логи, `Debug` и сообщения об ошибках.
